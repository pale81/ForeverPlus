# ForeverPlus database sources and limits

## Bundled dataset

`Data/Database.lua` is generated from three pinned MIT quest tables of Everything Quests: `QuestCoords_Forever.lua` (one general objective-area point), `QuestTurnIn_Forever.lua` (all known hand-in alternatives) and `QuestAvailable_Forever.lua` (quest start points, English name fallbacks and start requirements), commit `fe5fe092b3fe53bf31d43b82d185a396ab5cb21c`. The importer converts the packed map fractions to zone percentages (0–100) for all three point types, imports only NPC and object quest givers (skipping mob item-drop spawn lists, kind 3) with at most one primary location per distinct giver per map (entries are ordered densest first upstream), and includes profession skill and max-level gates. File hashes and the source revision are stored in the database metadata. The snapshot has 4700 quests (about 0.9 MB, 40 ms to load).

The quest tables are adapted from [Everything Quests](https://github.com/wheelbarrel00/EverythingQuests), whose repository is MIT-licensed. Its README identifies 323 quests new to Forever and says 319 have pickup markers. Quest data from AllTheThings is called out separately by the upstream project and carries its own MIT notice. Both notices are included under `Data/ThirdParty/`. The imported start table includes source coordinates, English title fallbacks and selected level/race/class/prerequisite/exclusion rules. The waypoint tables do **not** contain quest descriptions, NPC/object spawn lists or per-objective associations. For an active quest, ForeverPlus uses the game's objective text and shows a general objective-area point; after objectives are complete it uses the known hand-in alternatives. A richer optional QuestieDB provider can supply per-objective points. The MIT licence does not itself grant rights to Blizzard-owned underlying game content.

**Seasonal quest markers.** The importer uses [the holiday quest IDs and gift windows loaded by Everything Quests on Forever](https://github.com/wheelbarrel00/EverythingQuests/blob/fe5fe092b3fe53bf31d43b82d185a396ab5cb21c/Data/QuestHolidays_Classic.lua) at the same pinned revision. It also tags the five bundled Stranglethorn Fishing Extravaganza quests (8193, 8194, 8221, 8224 and 8225). ForeverPlus reads the in-game calendar for the event's start and end and identifies events by the banner texture IDs from the Forever client tables [Holidays](https://wago.tools/db2/Holidays?build=1.60.1.71037) and [HolidayDescriptions](https://wago.tools/db2/HolidayDescriptions?build=1.60.1.71037), including Darkmoon Faire's two venues. Known seasonal markers require a matching active calendar entry. Coverage depends on the quest associations and the calendar categories enabled in the client.

**Recipe vendors.** `Data/Radar.lua` (30 KB) is generated by `tools/build_radar.lua` from the Forever data of AllTheThings (MIT, notice in `Data/ThirdParty/`): vendors with map positions, the recipe items they sell and drop counts. Names are English (the compiled data has none; they are read from the comments of the source tables). Run `lua5.1 tools/build_radar.lua <ATT checkout> . <client build>` to refresh it.

**Flight points and instance entrances.** `Data/Points.lua` is generated by `tools/build_points.lua` from the Forever data of AllTheThings (flight points: node, flight master, position, faction) and the game tables TaxiNodes, Map (the corpse position of an instance is its entrance) and AreaTable as CSV (wago.tools/db2 for the client build, now 1.60.1.70862; ATT checkout `1528abd8`). Flight node settlements are matched to AreaTable IDs and localized by the client. German flight master titles in `Locales/deDE.lua` translate the roles, with individual titles where the NPC has a distinct role or gender. Instances whose ATT area is an outdoor area are matched by ATT's own instance ID (Excavation Site: Wetlands). Innkeepers have no open source yet and still come from the optional QuestieDB.

**Item catalog (not shipped).** An earlier snapshot also contained the 27k-item catalog of AHledger's public API. It was removed from the shipped file: none of ForeverPlus's features can use items without vendor, drop or spawn data, and it cost 4 MB and about 22 MB of memory. `python3 tools/build_database.py --items` adds it again. AHledger's [API terms](https://ahledger.com/terms) (updated 2026-09-19) allow personal and commercial use of the public API if the data is credited with a link wherever it is shown and is not resold as a feed; item names, icons and game data belong to Blizzard.

## What is and is not included

Quest rows contain the bundled point and availability fields described above. ForeverPlus keeps other unknown relations empty instead of deriving them from another database.

The current snapshot contains **no bundled item, NPC, entity spawn, object, vendor, loot, quest description or per-objective data**. It does include English quest-title fallbacks and quest-start coordinates. Recipe-map vendor pins, flight master, inn and instance entrance symbols, loot sources and detailed per-objective pins still require a richer provider (QuestieDB when installed); bundled waypoint rows supply general objective and hand-in points. Gaps are to be filled with openly licensed data or with observations players record themselves (`/fp daten`, see below). Start pins apply known level/race/class/prerequisite rules, but not every possible reputation or event requirement. The Quest tracker still uses the in-game quest APIs for active quest state.

Local observation capture remains opt-in (`/fp daten an|aus|löschen`) and stores client-visible quest titles/objectives separately in SavedVariables. The WoW client does not expose arbitrary hidden server data, full quest descriptions, drop probabilities, or coordinates for every entity through supported addon APIs. No local observation is silently merged into the shipped snapshot.

## Sources reviewed

**Weapon proc rate.** `Data/ProcRates.lua` holds the procs per minute of 192 chance-on-hit weapons from [WoWSims Forever's weapon proc table](https://github.com/wowsims/forever/blob/07648faf129cd82f99f4dd9e63b015f59f8ec811/tools/database/overrides/weapon_procs.go) (MIT, notice in `Data/ThirdParty/`, commit `07648faf129c`). 108 rates were measured from Forever combat logs (the table's `EV-` sources, documented in its `docs/evidence`), 55 are log fits not yet validated, 29 are carried over from Classic or TBC; the file keeps that kind per weapon and the tooltip names it. Forever's own tables state no rate for nearly all of these weapons: of 454 chance-on-hit weapon effects in build 1.60.1.70938 ([ItemEffect](https://wago.tools/db2/ItemEffect?build=1.60.1.70938), [SpellAuraOptions](https://wago.tools/db2/SpellAuraOptions?build=1.60.1.70938)), 285 have no proc row, 167 the 100/101 placeholder and 2 a real chance. Weapons without an entry count at the median of the Forever measurements, 1.95 per minute. Run `python3 -I tools/build_proc_rates.py <weapon_procs.go> <commit>` to refresh it. Earlier community measurements for Classic ([Classic-WoW-Armaments](https://github.com/TheGroxEmpire/Classic-WoW-Armaments/blob/main/chance_on_hit_items.md), no licence, not bundled) were mostly near 1 per minute. The conversion follows [Procs per minute](https://warcraft.wiki.gg/wiki/Procs_per_minute). No rate has been published or measured for Forever. The effect texts for extra attacks and attack speed (Thrash Blade, Ironfoe, Hand of Justice, Empyrean Demolisher) were checked in English and German against the [Wowhead Classic tooltips](https://www.wowhead.com/classic/item=17705). The weapon speed rating follows the [WoWSims Forever engine](https://github.com/wowsims/forever/blob/master/sim/core/attack.go) (MIT): instant attacks add the weapon's base damage with attack power at the normalized speed (2H 3.3, dagger 1.7, other one-hand 2.4, ranged 2.8), while Slam and Seal of Command (7 procs per minute, 70% weapon damage) scale attack power with the real speed. Spell IDs of all ranks come from its generated spell data. The uses per minute are rotation estimates, not simulated. Forever differs from Classic in two places the rating uses. Instant Poison deals less base damage in Forever (rank VI averages 88 instead of 130: [SpellEffect](https://wago.tools/db2/SpellEffect?build=1.60.1.70938) `EffectBasePointsF` with `Variance` against Classic Era 1.15.9's base points and die sides) and adds 1% of attack power; its 20% chance per hit is the same ([SpellItemEnchantment](https://wago.tools/db2/SpellItemEnchantment?build=1.60.1.70938) enchants 323–625, [WoWSims poisons](https://github.com/wowsims/forever/blob/master/sim/rogue/poisons.go)). Windfury has a 1.5 s recovery and Flametongue adds fire to every main-hand hit; their values come from the spell text as in the DPS simulator. Weapon skill works as in Classic ([WoWSims attack table](https://github.com/wowsims/forever/blob/master/sim/core/target.go): 0.1% less miss and dodge per point within ten points of the target's defense); the rating counts 0.2% hit per point and leaves out glancing blows. The weapon skill and creature attack power texts were checked on Edgemaster's Handguards, Aged Core Leather Gloves, Seal of the Dawn and Mark of the Champion.

**Solo Party lettering.** The cards use the current interface font selected in ForeverPlus, with a dark shadow and separate sizes for labels, amounts and record percentages.

**Solo Party effects.** The animated profession book is the visual reference for individual particles. The comic frames, water effects, leaves, strands, steam, healing sparks and feathered mask use separate textures in `Media/`. The game also renders its own smoke, sparkles and coin textures. Optional Bloody artwork uses a separate crimson card and four comic blood-splash sprites in `Media/SoloPartyBloody.tga` and `Media/SoloPartyBloodSplats.tga`.

**Solo Party critical sounds.** Two-handed sword critical flesh impacts 01–03 use FileDataIDs 1240622–1240624. Two-handed axe critical flesh impacts 01–03 use 1324858–1324860. The [community listfile](https://github.com/wowdev/wow-listfile) maps these IDs to paths. With curl and FFmpeg on PATH, `python3 tools/build_crit_sounds.py --build 1.60.1.71037` fetches the originals for that build via [Wago Tools](https://wago.tools/files) and writes local MP3s at −3 dB gain in `Media/LocalCrit/`. Pass `--source <directory>` instead when the original `<FileDataID>.ogg` files are available locally. Playback uses the effects channel and falls back to the same FileDataID when the local copy cannot play.

**Ambient sounds.** `Data/EmitterSounds.lua` joins the Forever 1.60.1.71037 [SoundEmitters](https://wago.tools/db2/SoundEmitters?build=1.60.1.71037), `SoundEmitterPillPoints`, `AreaTable`, `UiMapAssignment`, `SoundAmbience`, `SoundAmbienceFlavor`, `SoundKit`, `SoundKitEntry` and `SoundKitChild` DB2 exports. It covers sound sources placed in those tables and the ambience of mapped zones. The Rain filter uses `Weather` type 1 links and legacy rain SoundKits 8533–8535, restricted to named rain loops under `sound/ambience/weather/`. Rain files are listed across the build because the active weather sound cannot be read through the add-on API. Distance uses the source position or closest point on its path and the kit's cutoff plus 100 game units. It does not resolve prop emitters embedded in world models, phase conditions or currently playing sounds. The [wowdev community listfile release 202611211242](https://github.com/wowdev/wow-listfile/releases/tag/202611211242) supplies optional paths. The category labels use explicit terms in filenames and the verified rain IDs. Mixed filename cues, placement names and archive folders supply marked guesses. The nearest placement can refine a guess for a reused file. Records with insufficient or conflicting evidence go under Unclear. Playback uses the game files by FileDataID. Regenerate with `python3 tools/build_emitter_sounds.py <community-listfile.csv> <DB2 CSV directory> 1.60.1.71037`.

**Landing sounds.** `Modules/Landing.lua` references native sounds by FileDataID through `PlaySoundFile`. Classic footsteps `Sound/CHARACTER/FOOTSTEPS/mFootSmallDirt` A–E use 540227, 540136, 540099, 540201 and 540128. Thuds `Sound/DOODAD/FX_DeathThud_DirtGrass_med_01`–`06` use 950654, 950656, 950658, 950660, 950662 and 950664. Names are mapped by the [community listfile](https://github.com/wowdev/wow-listfile). Audio stays in the game installation.

Then run `tools/build_dungeon_bosses.py` with the pinned MoP and Retail journal exports and the Forever `SpellName.csv`. The generator reads the encounter and tile IDs from the generated journal and validates the curated encounter data.

The gear scorer uses the Forever client to convert combat ratings to percentage points. The fallback ratios come from [WoWSims' Forever rating table](https://github.com/wowsims/forever/pull/571) and the [in-game item check reported by NaowhForever](https://github.com/naowh-gaming/NaowhForever/pull/137). Blizzard documents shared hit and critical strike in its [Forever deep dive](https://worldofwarcraft.blizzard.com/en-us/news/24303313).

**PvE scoring profiles (`Modules/Items.lua`).** The 27 talent trees each have their own profile. Feral also has a selectable Bear profile. The damage estimates are based on [MythicSim's Forever reference builds](https://www.mythicsim.com/wow-forever/stat-priority) (engine `a667dce84`, client 1.60.1.70707), particularly the relative values of attributes, attack power, spell damage, hit, crit, expertise and haste. Combat-rating weights use the equivalent amount of rating for one percentage point. The addon rounds EP and adds allowances for weapon upgrades, mana, and health during leveling. [Blizzard's November 10 hotfixes](https://news.blizzard.com/en-us/article/24315281/wow-forever-hotfixes-november-11-2026) inform the Enhancement and Affliction adjustments. [Blizzard's Druid class deep dive](https://worldofwarcraft.blizzard.com/en-us/news/24301515) confirms that weapon DPS applies to both Feral forms and explains how Defense skill contributes to Bear armor. Passive stat-conversion and percentage stat-multiplier talents are adjusted dynamically to the character's active learned ranks (`C_Traits`) using the exact rank curves from Forever build `1.60.1.71037` ([SpellEffect](https://wago.tools/db2/SpellEffect?build=1.60.1.71037), [TraitDefinitionEffectPoints](https://wago.tools/db2/TraitDefinitionEffectPoints?build=1.60.1.71037), [CurvePoint](https://wago.tools/db2/CurvePoint?build=1.60.1.71037)): Divine Strength, Divine Intellect, Toughness, Shield Specialization and Champion of the Light (Paladin); Careful Aim, Lightning Reflexes and Survivalist (Hunter); Mental Strength and Spiritual Guidance (Priest); Ancestral Knowledge, Mental Dexterity, Mental Quickness, Toughness and Improved Reincarnation (Shaman); Arcane Mind and Arcane Resilience (Mage); Demonic Embrace (Warlock); Heart of the Wild, Living Spirit, Natural Instinct and Thick Hide (Druid). Warrior and Rogue have no passive stat-conversion or percentage stat-multiplier talents in this build.

The five healer profiles draw on the Forever priorities for [Holy Paladin](https://www.icy-veins.com/wow-forever/holy-paladin-healer-pve-stat-priority), [Discipline Priest](https://www.icy-veins.com/wow-forever/discipline-priest-healer-pve-stat-priority), [Holy Priest](https://www.icy-veins.com/wow-forever/holy-priest-healer-pve-stat-priority), [Restoration Shaman](https://www.icy-veins.com/wow-forever/restoration-shaman-healer-pve-stat-priority) and [Restoration Druid](https://www.icy-veins.com/wow-forever/restoration-druid-healer-pve-stat-priority). The tank profiles combine mitigation priorities from the [Protection Warrior guide](https://www.icy-veins.com/wow-forever/protection-warrior-tank-pve-stat-priority), [Feral Druid guide](https://www.icy-veins.com/wow-forever/feral-druid-melee-dps-and-tank-pve-stat-priority) and [Protection Paladin guide](https://www.wowhead.com/forever/guide/classes/paladin/protection/stat-priority-pve-tank) with threat estimates. These profiles approximate marginal value before the relevant caps. Character gear, target, fight duration and rotation affect the actual values.

Protection Paladin attack power is a threat estimate based on the profile's Strength weight and [the two attack power per Strength modeled by WoWSims](https://github.com/wowsims/forever/blob/master/sim/paladin/paladin.go); Strength also contributes to block value. Flat attack power comes from the client stats or, if missing, the English or German Equip line. The client tooltip supplies the Humanoid bonus separately. The two Equip lines on the Catacomb Cloak (279899) provide the regression example.

## Rebuild

Requirements: Python 3 and network access to `raw.githubusercontent.com` (and `ahledger.com` with `--items`). From the addon directory:

```sh
python3 tools/build_database.py
```

To target another client build explicitly:

```sh
python3 tools/build_database.py --client-build 1.60.1.70862
```

The build fetches the three Everything Quests files at the pinned commit; with `--items` it also fetches the 12 AHledger catalog classes listed in `tools/data_sources.json`. It validates row shapes and coordinates, rejects conflicting item IDs, and writes the snapshot. It records the capture date, client build, upstream commit, and content hashes. Review generated diffs before publishing; AHledger's results (with `--items`) are live and may change, so refresh the licence/terms check then. Review any upstream pin change before updating the manifest.

## Local observations and data quality

Observation capture is off by default. `/fp daten an` saves client-visible quest titles and objective snapshots to `ForeverPlusDB` under `observations`; `/fp daten aus` stops it, `/fp daten` reports status, and `/fp daten löschen` clears it. Entries include quest IDs, time and capture method. Repeated identical objectives are deduplicated; history is capped at 20 snapshots per quest and 200 quests. This is local user state and is not sent anywhere or included by the build.

The validator checks sorted unique IDs, row shapes, counts, source metadata, response hashes, and that quest point lists contain valid map coordinates. Lua syntax and the addon's host API still need separate checks; no live-client test is implied by a successful data build.

`Data/LootEG.lua` ships 1,313 creatures and 2,024 distinct loot items across all source types. It combines player contributions with the Efficient Games snapshot of 2026-11-18 through client build 1.60.1.70959. The generator includes Beta and live `wowf` observations, using the Beta copy when both folders contain the same build's loot export. This avoids counting the older records published again under the live product code. Fishing, skinning, pickpocketing and encounter-roll samples are kept out of the corpse statistics. Forever hands out boss loot as group rolls per encounter, so the encounter rolls are kept separately (`encounters`, by DungeonEncounter ID, share per recorded kill; kills under different loot thresholds count together): 85 encounters. Regenerate with `python3 tools/build_eg.py <EG checkout> --loot-only`. The Loot tab of the dungeon journal shows the encounter rolls first and adds corpse statistics and the player's own loot windows of creatures with the boss's English or German name. Together this covers 88 of the 333 journal encounters in this snapshot; the export has no raid kills yet. [Efficient Games data, CC BY 4.0](https://github.com/JIVESCORP/eg-link-output-wowf/tree/30c3bb9c8e792208feab362357471603dc51e12e)

The Shift mouseover block adds local observations to the shipped counts. Local recording counts each item at most once per corpse or node. Imported counts can include several slots for one item in a window. The tooltip shows recorded drops divided by loot windows and displays the raw count when drops exceed windows. The figures describe loot windows you can open and can vary with group loot and active quests. [Efficient Games loot dataset](https://github.com/JIVESCORP/eg-link-output-wowf/blob/ea970da071079b32e56f349e09648ff0e314b351/DATASETS.md#loot)
