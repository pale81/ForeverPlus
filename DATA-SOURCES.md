# ForeverPlus database sources and limits

## Bundled dataset

`Data/Database.lua` is generated from three pinned MIT quest tables of Everything Quests: `QuestCoords_Forever.lua` (one general objective-area point), `QuestTurnIn_Forever.lua` (all known hand-in alternatives) and `QuestAvailable_Forever.lua` (quest start points, English name fallbacks and start requirements), commit `fe5fe092b3fe53bf31d43b82d185a396ab5cb21c`. File hashes and the source revision are stored in the database metadata. The snapshot has 4700 quests (about 1 MB, 40 ms to load).

The quest tables are adapted from [Everything Quests](https://github.com/wheelbarrel00/EverythingQuests), whose repository is MIT-licensed. Its README identifies 323 quests new to Forever and says 319 have pickup markers. Quest data from AllTheThings is called out separately by the upstream project and carries its own MIT notice. Both notices are included under `Data/ThirdParty/`. The imported start table includes source coordinates, English title fallbacks and selected level/race/class/prerequisite/exclusion rules. The waypoint tables do **not** contain quest descriptions, NPC/object spawn lists or per-objective associations. For an active quest, ForeverPlus uses the game's objective text and shows a general objective-area point; after objectives are complete it uses the known hand-in alternatives. A richer optional QuestieDB provider can supply per-objective points. The MIT licence does not itself grant rights to Blizzard-owned underlying game content.

**Recipe vendors.** `Data/Radar.lua` (30 KB) is generated by `tools/build_radar.lua` from the Forever data of AllTheThings (MIT, notice in `Data/ThirdParty/`): vendors with map positions, the recipe items they sell and drop counts. Names are English (the compiled data has none; they are read from the comments of the source tables). Run `lua5.1 tools/build_radar.lua <ATT checkout> . <client build>` to refresh it.

**Flight points and instance entrances.** `Data/Points.lua` is generated by `tools/build_points.lua` from the Forever data of AllTheThings (flight points: node, flight master, position, faction) and the game tables TaxiNodes, Map (the corpse position of an instance is its entrance) and AreaTable as CSV (wago.tools/db2 for the client build, now 1.60.1.70862; ATT checkout `1528abd8`). Flight node settlements are matched to AreaTable IDs and localized by the client. German flight master titles in `Locales/deDE.lua` translate the roles, with individual titles where the NPC has a distinct role or gender. Instances whose ATT area is an outdoor area are matched by ATT's own instance ID (Excavation Site: Wetlands). Innkeepers have no open source yet and still come from the optional QuestieDB.

**Item catalog (not shipped).** An earlier snapshot also contained the 27k-item catalog of AHledger's public API. It was removed from the shipped file: none of ForeverPlus's features can use items without vendor, drop or spawn data, and it cost 4 MB and about 22 MB of memory. `python3 tools/build_database.py --items` adds it again. AHledger's [API terms](https://ahledger.com/terms) (updated 2026-09-19) allow personal and commercial use of the public API if the data is credited with a link wherever it is shown and is not resold as a feed; item names, icons and game data belong to Blizzard.

## What is and is not included

Quest rows contain the bundled point and availability fields described above. ForeverPlus keeps other unknown relations empty instead of deriving them from another database.

The current snapshot contains **no bundled item, NPC, entity spawn, object, vendor, loot, quest description or per-objective data**. It does include English quest-title fallbacks and quest-start coordinates. Recipe-map vendor pins, flight master, inn and instance entrance symbols, loot sources and detailed per-objective pins still require a richer provider (QuestieDB when installed); bundled waypoint rows supply general objective and hand-in points. Gaps are to be filled with openly licensed data or with observations players record themselves (`/fp daten`, see below). Start pins apply known level/race/class/prerequisite rules, but not every possible reputation or event requirement. The Quest tracker still uses the in-game quest APIs for active quest state.

Local observation capture remains opt-in (`/fp daten an|aus|löschen`) and stores client-visible quest titles/objectives separately in SavedVariables. The WoW client does not expose arbitrary hidden server data, full quest descriptions, drop probabilities, or coordinates for every entity through supported addon APIs. No local observation is silently merged into the shipped snapshot.

## Sources reviewed

**Quest hand-in pins.** With Blizzard's Quest Objectives filter off, ForeverPlus reads the Forever client's quest log for readiness and takes the map position from `C_QuestLog.GetQuestsOnMap`. When the client supplies no usable point for the quest on that map, the pins use the bundled `turnInPoint` coordinates described above.

**Group finder dungeon levels.** The dungeon filter and search results read the recommended levels from the Forever client's `C_LFGList.GetActivityInfoTable`. Each wing uses its own activity ID.

**Dungeon journal.** `Data/DungeonJournal.lua` lists the 30 dungeon maps and 12 raid maps in `GroupFinderActivity` for Forever build `1.60.1.70938`. Wings that share a map ID appear together. The activity suggestions supply the displayed level ranges. Names, encounter order and banner textures come from the game's [Map](https://wago.tools/db2/Map?build=1.60.1.70938), [DungeonEncounter](https://wago.tools/db2/DungeonEncounter?build=1.60.1.70938) and [LoadingScreens](https://wago.tools/db2/LoadingScreens?build=1.60.1.70938) tables. Dungeon encounters use the normal and shared difficulty rows. The Molten Core completion record is omitted from the boss list.

The journal references Blizzard textures by file ID. Classic floor plans use paths catalogued in the [wowdev community listfile](https://github.com/wowdev/wow-listfile). The other maps use the Forever WDT minimap grid. Blank borders are cropped, and disconnected regions are shown on separate pages. Classic layouts can differ from Forever. A minimap view can leave out underground rooms or upper floors. Entrance maps reuse the existing world map entrance data. Boss locations are unavailable in these sources.

Quest IDs, faction, class and minimum level come from the MIT-licensed `db/Camelot/Categories/Instances.lua` at [AllTheThings revision ca9d306](https://github.com/ATTWoWAddon/AllTheThings/blob/ca9d30669a5759111a0889d32d6fd674241bab3c/db/Camelot/Categories/Instances.lua). This includes some quests leading to the instance. The Shaper's Terrace and Karazhan Crypts add individual quest IDs corroborated by [Icy Veins](https://db.icy-veins.com/wow-forever/quests/zones/the-shaper-s-terrace/) and [Legacy of Warcraft](https://legacyofwarcraft.com/db/forever/quests/karazhan-crypts.html). IDs must exist in the client's `QuestV2` table. Quest names and progress use client APIs, with English fallback titles and pickup points from the bundled quest data when available. Active quests filed under the instance name can supplement the list. Coverage varies by instance.

To regenerate, export the relationships with `lua5.1 tools/dungeon_quests.lua <ATT checkout>` and pass that export, the client tables, WDTs, local BLP files and the community listfile to `tools/build_dungeon_journal.py`.

The gear scorer uses the Forever client to convert combat ratings to percentage points. The fallback ratios come from [WoWSims' Forever rating table](https://github.com/wowsims/forever/pull/571) and the [in-game item check reported by NaowhForever](https://github.com/naowh-gaming/NaowhForever/pull/137). Blizzard documents shared hit and critical strike in its [Forever deep dive](https://worldofwarcraft.blizzard.com/en-us/news/24303313).

**PvE scoring profiles (`Modules/Items.lua`).** The 27 talent trees each have their own profile. Feral also has a selectable Bear profile. The damage estimates are based on [MythicSim's Forever reference builds](https://www.mythicsim.com/wow-forever/stat-priority) (engine `a667dce84`, client 1.60.1.70707), particularly the relative values of attributes, attack power, spell damage, hit, crit, expertise and haste. Combat-rating weights use the equivalent amount of rating for one percentage point. The addon rounds EP and adds allowances for weapon upgrades, mana, and health during leveling. [Blizzard's November 10 hotfixes](https://news.blizzard.com/en-us/article/24315281/wow-forever-hotfixes-november-11-2026) inform the Enhancement and Affliction adjustments. [Blizzard's Druid class deep dive](https://worldofwarcraft.blizzard.com/en-us/news/24301515) confirms that weapon DPS applies to both Feral forms and explains how Defense skill contributes to Bear armor.

The five healer profiles draw on the Forever priorities for [Holy Paladin](https://www.icy-veins.com/wow-forever/holy-paladin-healer-pve-stat-priority), [Discipline Priest](https://www.icy-veins.com/wow-forever/discipline-priest-healer-pve-stat-priority), [Holy Priest](https://www.icy-veins.com/wow-forever/holy-priest-healer-pve-stat-priority), [Restoration Shaman](https://www.icy-veins.com/wow-forever/restoration-shaman-healer-pve-stat-priority) and [Restoration Druid](https://www.icy-veins.com/wow-forever/restoration-druid-healer-pve-stat-priority). The tank profiles combine mitigation priorities from the [Protection Warrior guide](https://www.icy-veins.com/wow-forever/protection-warrior-tank-pve-stat-priority), [Feral Druid guide](https://www.icy-veins.com/wow-forever/feral-druid-melee-dps-and-tank-pve-stat-priority) and [Protection Paladin guide](https://www.wowhead.com/forever/guide/classes/paladin/protection/stat-priority-pve-tank) with threat estimates. These profiles approximate marginal value before the relevant caps. Character gear, target, fight duration and rotation affect the actual values.

## Rebuild

Requirements: Python 3 and network access to `raw.githubusercontent.com` (and `ahledger.com` with `--items`). From the addon directory:

```sh
python3 tools/build_database.py
```

To target another client build explicitly:

```sh
python3 tools/build_database.py --client-build 1.60.1.70862
```

The build fetches the three Everything Quests files at the pinned commit; with `--items` it also fetches the 12 AHledger catalog classes listed in `tools/data_sources.json`. It validates row shapes and coordinates, rejects conflicting item IDs, and writes the snapshot. It records the capture date, client build, upstream commit, and content hashes. Review generated diffs before publishing; AHledger's results (with `--items`) are live and may change, so refresh the licence/terms check then. Review any upstream pin change before updating the manifest.

## Local observations and data quality

Observation capture is off by default. `/fp daten an` saves client-visible quest titles and objective snapshots to `ForeverPlusDB` under `observations`; `/fp daten aus` stops it, `/fp daten` reports status, and `/fp daten löschen` clears it. Entries include quest IDs, time and capture method. Repeated identical objectives are deduplicated; history is capped at 20 snapshots per quest and 200 quests. This is local user state and is not sent anywhere or included by the build.

The validator checks sorted unique IDs, row shapes, counts, source metadata, response hashes, and that quest point lists contain valid map coordinates. Lua syntax and the addon's host API still need separate checks; no live-client test is implied by a successful data build.

The Shift mouseover block for enemies uses the existing creature records in `Data/LootEG.lua` and adds local observations. Its percentages are recorded item drops divided by the number of recorded loot windows for that creature. The imported counts can include several slots for one item in a window. When the count exceeds the number of windows, the tooltip shows the raw counts. The figures describe the observed loot windows and can vary with group loot and active quests. [Efficient Games loot dataset](https://github.com/JIVESCORP/eg-link-output-wowf/blob/main/DATASETS.md#loot)

## Place texts

`Data/PlaceInfo.lua` holds short texts (German and English) about 55 towns and capitals of the Eastern Kingdoms and Kalimdor (names of regions, places and dungeons are filled in from the client at runtime, so they read in the client's language), shown when the place name is hovered on the world map. The texts were written for this addon from general knowledge of the game world, in its own words, and state facts only; nothing was copied from a wiki or from game text. They are not checked against a source. The Warcraft Wiki (CC BY-SA, share-alike) was considered and not used so that no share-alike duty attaches to the data.

## Edit Mode layouts

`Data/EditModeLayouts.lua` holds layout texts as the game's Edit Mode exports them (layout menu: share). The text of "Base layout" was made and handed in by the project owner; it contains only positions and settings of the game's own interface elements.

## Area texts

`ns.AreaInfo` in `Data/PlaceInfo.lua` is keyed by area IDs of the AreaTable (wago.tools/db2, build 1.60.1.70862, checked against the same CSV as `tools/places.py` uses: AreaPOI, AreaTable, UiMapAssignment; regenerating `Data/Places.lua` from them gives the same 59 places; no area of 70291 was removed or renamed in 70862). Texts are the authors' own, from general knowledge, unchecked against a source.

## Paladin blessings

The buff reminder uses an add-on rule of recipient level 10 for Blessing of Kings. The automatic tank order prioritizes the attributes from Kings and the mana regeneration from Wisdom. Blizzard's class overview describes the Protection Paladin's Holy threat and mana mechanics and the move of Kings to the baseline spellbook. [Blizzard's Forever Paladin overview](https://worldofwarcraft.blizzard.com/en-gb/news/24302099/world-of-warcraft-forever-class-deep-dives-paladin)

## Talent calculator links (Modules/Talents.lua, `LINK_IDS`)

The planner reads links of the Forever talent calculators of wowhead.com and icy-veins.com. No data of either site is shipped except what is needed to read their addresses: for Icy Veins the character that stands for each talent in its link (per class and tree, in the order of the tree; read from the calculator on 11 November 2026, the site's data version 70888-0650090c). Names, texts, icons and tooltips of the sites are not used; the talents themselves come from the game.
